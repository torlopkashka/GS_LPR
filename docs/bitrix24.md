# Бот Битрикс24 и сторож Uptime Kuma

Уведомления о проездах и управление воротами работают через чат-бота в Битрикс24.
О пропаже связи с объектом сообщает Uptime Kuma на VPS: тоже в Битрикс24, плюс по желанию SMS.

```
 ПК у ворот ──(исходящие запросы)──► Битрикс24 ◄── сотрудники (чат «Ворота», кнопки)
      │                                  ▲
      └── сигнал «я жив» раз в минуту ──► Uptime Kuma на VPS ── тревога, если сигналов нет
```

Боту не нужен белый IP или публичный адрес. Он работает в режиме «Чат-боты 2.0» (`imbot.v2`,
режим `fetch`): каждые 3 секунды сам забирает новые команды из Битрикс24.

## Что умеет бот

**Кнопки** под сообщениями бота:

| Кнопка | Что делает |
|---|---|
| 🔓 Открыть ворота | подаёт команду на ворота и отвечает, прошла ли она |
| 📡 Статус | состояние сервера, агента ворот и камер, последний обрыв интернета, последний номер |
| 🕘 Последние | последние 10 событий журнала |
| 📋 Номера | список разрешённых номеров со сроками |

**Команды** (вводятся в чате, Битрикс24 подсказывает их после `/`):

```
/add А123ВС77 Иванов                 добавить номер (владелец необязателен)
/add А123ВС77 Гость до 31.12.2026    временный доступ до даты включительно
/del А123ВС77                        удалить номер
/open  /status  /last  /list  /help
```

**Уведомления** в чат «Ворота»:
- ✅ проезд разрешён: фото, номер, владелец, камера;
- ⛔ неизвестный номер: фото и кнопки **«🔓 Открыть ворота»** (действует 15 минут) и **«➕ В список»**;
- ⚠️ агент ворот не на связи дольше 30 с, то есть автоматическое открытие не работает;
- ⚠️ нет видео с камеры дольше 2 минут;
- ✅ когда агент или камера восстановились, с длительностью простоя;
- 🔌 **связь с объектом восстановлена**: сколько не было интернета и сколько машин за это время
  проехало или получило отказ.

Управлять воротами могут только сотрудники из `B24_USER_IDS`. Остальным бот отвечает
«Нет доступа» и называет их ID. Так удобно узнать ID нового сотрудника.

## Как бот ведёт себя при отключении интернета на объекте

1. **Ворота продолжают работать**: распознавание, агент и реле работают по локальной сети. Пульты тоже.
2. **Бот не отвечает.** Если на «📡 Статус» ответа нет, на объекте нет интернета или выключен ПК.
3. **Нажатия во время обрыва не выполняются.** Битрикс24 хранит нажатия кнопок и отдаст их боту,
   когда связь вернётся. У каждого нажатия есть время. «Открыть», нажатое больше 2 минут назад
   (`max_command_age`), бот не выполнит, а ответит, что команда устарела.
4. **После восстановления** бот сам присылает отчёт об обрыве.
5. **Об обрыве сразу** сообщает Uptime Kuma (ниже). Сам бот на отключённом ПК сделать этого не может.

## Настройка бота

### 1. Входящий вебхук

В Битрикс24: **Разработчикам → Другое → Входящий вебхук** (в старом интерфейсе:
**Приложения → Вебхуки → Добавить вебхук → Входящий вебхук**).

- Права доступа: **Чат-боты (imbot)**.
- Сохраните и скопируйте адрес вида `https://ваш-портал.bitrix24.ru/rest/1/abcdef123456/`.

Адрес вебхука — это пароль к порталу в пределах выбранных прав. Храните его только в `.env`.
Вебхук работает от имени создавшего его сотрудника. Если этого сотрудника уволят или отключат,
бот перестанет работать. Лучше создать вебхук от имени администратора портала.

### 2. ID сотрудников

Откройте профиль сотрудника: в адресе будет `.../company/personal/user/15/`, где **15** и есть ID.
Если сотрудник напишет боту без доступа, бот тоже назовёт его ID.

### 3. `.env` на ПК у ворот

```
B24_WEBHOOK_URL=https://ваш-портал.bitrix24.ru/rest/1/abcdef123456/
B24_BOT_TOKEN=...          # setup.ps1 заполняет сам; не меняйте после первого запуска
B24_USER_IDS=1,15,27
B24_DIALOG_ID=             # оставьте пустым — бот сам создаст чат «Ворота»
```

Затем выполните `docker compose up -d`. При первом запуске бот:
- регистрируется в Битрикс24 под именем «Ворота»;
- регистрирует команды `/open`, `/status` и остальные;
- создаёт групповой чат **«Ворота»** с сотрудниками из `B24_USER_IDS` и пишет туда справку.

В журнале сервера (`docker compose logs -f`) появится `Бот Битрикс24 готов`. На панели веб-интерфейса
будет строка «Битрикс24: бот на связи».

- **Новые сотрудники.** Добавьте ID в `B24_USER_IDS` и выполните `docker compose up -d`: бот сам
  добавит их в чат.
- **Личный диалог.** Можно писать боту и в личный диалог (найдите «Ворота» в поиске чатов).
  Уведомления приходят только в общий чат.
- **Свой чат.** Чтобы слать уведомления в уже существующий чат, добавьте в него бота и
  укажите `B24_DIALOG_ID=chat123` (номер чата виден в адресе чата в браузере).

## Uptime Kuma: уведомление, когда объект пропал со связи

Kuma ставится на VPS (подойдёт российский, доступ к Telegram не нужен). Сервер ворот раз в
минуту отправляет ему сигнал. Если сигналы прекратились, Kuma шлёт тревогу в Битрикс24.

### 1. Установка на VPS

```bash
curl -fsSL https://get.docker.com | sh
docker run -d --restart=always -p 3001:3001 -v uptime-kuma:/app/data \
  --name uptime-kuma louislam/uptime-kuma:2
```

Откройте `http://IP-VPS:3001`, выберите русский язык и создайте учётную запись администратора.
Панель открыта по обычному HTTP, поэтому закройте порт 3001 файрволом для всех, кроме своего IP
и IP объекта (или поставьте перед Kuma HTTPS-прокси).

### 2. Вебхук для Kuma

Создайте в Битрикс24 **ещё один** входящий вебхук, с правами **Мессенджер (im)**. Kuma
отправляет через него системное уведомление («колокольчик») конкретному сотруднику. Вебхук
бота для этого не подходит: у него другие права.

### 3. Уведомление в Kuma

**Настройки → Уведомления → Настроить уведомление**:
- Тип уведомления: **Bitrix24**;
- URL-адрес вебхука Bitrix24: адрес из шага 2;
- User ID: ID сотрудника, которому придёт тревога;
- нажмите «Тест»: в Битрикс24 у сотрудника появится уведомление.

Каждое уведомление Kuma отправляется одному сотруднику. Чтобы тревогу получали несколько человек,
создайте по уведомлению на каждого. Для надёжности можно добавить второй канал:
**SMSC** (SMS через smsc.ru) или **SMTP** (почта). В одном мониторе включаются сразу несколько каналов.

Цвет полоски в уведомлении Kuma для Битрикс24 может не соответствовать состоянию
(в Kuma 2.x он перепутан). Ориентируйтесь на текст: `[DOWN]` / `[UP]`.

### 4. Монитор

**Добавить монитор**:
- Тип монитора: **Push**;
- Название: «Ворота»;
- Интервал сердцебиения: **60** секунд;
- Повторы: **4**. Тревога придёт после ~5 минут тишины, короткие сбои её не вызовут;
- отметьте созданные уведомления;
- скопируйте **Push URL** вида `http://IP-VPS:3001/api/push/AbCdEf1234?status=up&msg=OK&ping=`.

На ПК у ворот впишите его в `.env` (часть после `?` можно убрать) и выполните `docker compose up -d`:

```
HEALTHCHECK_URL=http://IP-VPS:3001/api/push/AbCdEf1234
```

Через минуту монитор станет зелёным. Сервер шлёт `status=up`, пока всё в порядке. Если агент
ворот или камера пропали, он шлёт `status=down` с описанием («агент ворот не на связи»),
и Kuma сразу присылает тревогу. На странице Kuma видна история доступности объекта.

### Кто о чём сообщит

| Что случилось | Кто сообщит |
|---|---|
| агент ворот не на связи / нет видео, интернет есть | бот в чате «Ворота» и Kuma |
| пропал интернет на объекте, выключился ПК, завис Docker | Kuma, через ~5 минут |
| интернет вернулся | бот: отчёт об обрыве; Kuma: «UP» |

С ПК у ворот должны быть доступны портал Битрикс24 (`https://ваш-портал.bitrix24.ru`)
и Kuma (`http://IP-VPS:3001`). Проверка в PowerShell:
`Invoke-WebRequest http://IP-VPS:3001 -UseBasicParsing`.
