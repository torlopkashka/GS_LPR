# Настройка ПК у ворот (Windows 10 + Docker Desktop)

На ПК у ворот работает всё, что связано с воротами. Файлы лежат в папке `local/`:

| Что | Где работает | Что делает |
|---|---|---|
| `local/server` | Docker Desktop, контейнер `lpr` | распознавание номеров, решение об открытии, **основной список номеров**, журнал, веб-интерфейс `:8000`, обмен с ботом на VPS, сигнал в Uptime Kuma |
| `local/agent` | прямо в Windows (Python) | принимает команду от сервера и замыкает реле на воротах |

```
 G4 Pro ×2 ─► консоль UniFi Protect ─ RTSP по локальной сети ─┐
                                                               ▼
 ┌──────────────────────── ПК у ворот (Windows 10) ────────────────────────┐
 │  Docker Desktop: контейнер lpr                                          │
 │   распознавание · список номеров · журнал · веб :8000 ── HTTP ──────────┼──► VPS: бот Битрикс24 :8080
 │                      ▲ ws://127.0.0.1:8000                  └── HTTP ───┼──► VPS: Uptime Kuma :3001
 │  Windows: агент ворот (Python, планировщик задач) ── USB-реле ──────────┼──► NICE RB600
 └─────────────────────────────────────────────────────────────────────────┘
```

Ворота открываются **только автоматически** по номерам из списка или пультом. Кнопки
«Открыть» нет ни в веб-интерфейсе, ни в Битрикс24.

Интернет нужен только для обмена с VPS: уведомления, правки списка из Битрикс24, сигнал в Kuma.
Распознавание, открытие ворот, веб-интерфейс в локальной сети и журнал работают и без интернета.
Правки списка, отправленные в Битрикс24 во время обрыва, применятся, когда связь восстановится.

Агент работает не в Docker, а прямо в Windows, потому что Docker Desktop не даёт
контейнерам доступа к USB-устройствам.

**Перед началом** настройте VPS ([vps.md](vps.md)) и подготовьте:
- `VPS_URL` и `VPS_TOKEN` (их показывает `setup.sh` на VPS);
- Push URL монитора «Объект: ворота» из Uptime Kuma.

ПК можно настроить и раньше, а связь с VPS добавить потом (раздел 6).

## Требования к ПК

- Windows 10 64-bit (22H2) или Windows 11, включённая виртуализация (WSL2);
- процессор от 4 потоков, от 8 ГБ ОЗУ (сам сервер занимает около 1 ГБ, Docker/WSL ещё около 1 ГБ);
- проводное подключение к той же сети, что и консоль UniFi Protect.

## 1. Подготовить Windows к работе без присмотра

Компьютер должен сам подниматься после отключения света и не засыпать.

1. **BIOS/UEFI**: `Restore on AC Power Loss` (или `AC Back`, `After Power Failure`) → **Power On**.
2. **Электропитание**: «Панель управления → Электропитание → Настройка схемы» →
   «Переводить компьютер в спящий режим» → **Никогда**. Режим гибернации тоже отключить:
   `powercfg /h off` (в командной строке от администратора).
3. **Автоматический вход**. Docker Desktop запускается только после входа пользователя:
   `Win+R` → `netplwiz` → снять галочку «Требовать ввод имени пользователя и пароля»
   (в новых сборках сначала выключите «Параметры → Учётные записи → Варианты входа →
   Требовать вход с помощью Windows Hello»).
4. **Обновления Windows**: «Параметры → Обновление → Изменить период активности».
   Выставьте часы, когда перезагрузка безопаснее всего.
5. Для ПК задайте **постоянный IP** в роутере (резервирование DHCP), чтобы веб-интерфейс
   всегда открывался по одному адресу.

## 2. Docker Desktop

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) с
   бэкендом **WSL 2** (по умолчанию).
2. В Docker Desktop → **Settings → General** включите
   **Start Docker Desktop when you sign in to your computer**.
3. Ограничьте память WSL, чтобы Docker не забирал всю ОЗУ. Создайте файл
   `C:\Users\<имя>\.wslconfig`:
   ```ini
   [wsl2]
   memory=4GB
   processors=4
   ```
   и перезапустите Docker Desktop.

## 3. Включить RTSP на камерах

UniFi Protect → **Devices** → камера → **Settings → Advanced → RTSP**: включите поток
**Medium** (1280×720), для дальних машин **High**. Protect покажет адрес вида

```
rtsps://192.168.1.1:7441/AbCdEf1234567890?enableSrtp
```

Для сервера запишите его в незашифрованном виде: порт **7447**, схема `rtsp://`,
без `?enableSrtp`:

```
rtsp://192.168.1.1:7447/AbCdEf1234567890
```

Проверьте адрес в VLC («Медиа → Открыть URL»): видео должно открыться.

## 4. Сервер

1. Скачайте проект (`git clone https://github.com/torlopkashka/GS_LPR.git` или ZIP с GitHub)
   в папку, например `C:\gs-lpr`. Нужна только папка `local`.
2. Откройте PowerShell в папке `C:\gs-lpr\local` (в Проводнике: `Shift` + правый клик по
   папке → «Открыть окно PowerShell здесь») и выполните:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   Скрипт спросит:
   - пароль для веб-интерфейса;
   - IP-адрес VPS;
   - `SITE_TOKEN` с VPS (последние два можно пропустить клавишей Enter и указать позже).

   Затем он создаст `.env` со случайными ключами и `server\config.yaml`, соберёт и
   запустит контейнер. Первая сборка занимает 5–10 минут.
3. Откройте `server\config.yaml` в Блокноте (`notepad server\config.yaml`), впишите RTSP-адреса
   камер и перезапустите сервер:
   ```powershell
   docker compose restart
   ```
4. Откройте http://localhost:8000 (с других устройств в сети: `http://IP-компьютера:8000`)
   и войдите с логином `admin` и своим паролем. На панели должно появиться видео с камер.

Контейнер перезапускается сам (`restart: unless-stopped`) и поднимается вместе с Docker Desktop.

## 5. Агент ворот

1. Установите [Python 3.11+](https://www.python.org/downloads/windows/). При установке
   отметьте **Add python.exe to PATH** и в «Customize installation» выберите
   **Install for all users**. Агент запускается от системной учётной записи, и Python должен быть доступен всем пользователям.
2. Подключите USB-реле. Для реле на CH340 номер порта смотрите в Диспетчере устройств
   → «Порты (COM и LPT)» → `USB-SERIAL CH340 (COM3)`.
3. PowerShell **от имени администратора** (Пуск → PowerShell → правый клик → «Запуск от имени
   администратора»), перейдите в папку агента и запустите установку:
   ```powershell
   cd C:\gs-lpr\local\agent
   powershell -ExecutionPolicy Bypass -File .\install-windows.ps1
   ```
   Скрипт создаст окружение Python и файл `agent.yaml` (с токеном из `.env`) и зарегистрирует
   задачу «GS-LPR Gate Agent», которая стартует при включении компьютера.
4. Откройте `agent.yaml` (`notepad agent.yaml`), проверьте `driver` и `port`, затем проверьте реле:
   ```powershell
   .\venv\Scripts\python.exe gate_agent.py -c agent.yaml --test
   ```
   Реле должно щёлкнуть, ворота открыться.
5. Запустите агент:
   ```powershell
   Start-ScheduledTask -TaskName "GS-LPR Gate Agent"
   Get-Content .\agent.log -Wait
   ```
   В журнале появится `Подключено к ws://127.0.0.1:8000/ws/agent`, на панели «Агент ворот: на связи».

Подключение проводов к приводу описано в [gate-control.md](gate-control.md).

## 6. Связь с VPS: бот Битрикс24 и Uptime Kuma

1. Откройте `C:\gs-lpr\local\.env` в Блокноте (`notepad .env` в папке `local`) и заполните:
   ```ini
   VPS_URL=http://203.0.113.10:8080
   VPS_TOKEN=значение SITE_TOKEN из vps/.env
   HEALTHCHECK_URL=http://203.0.113.10:3001/api/push/AbCdEf1234
   ```
   - `VPS_URL` — IP вашего VPS и порт 8080;
   - `VPS_TOKEN` — должен совпадать с `SITE_TOKEN` на VPS символ в символ;
   - `HEALTHCHECK_URL` — Push URL монитора «Объект: ворота» из Kuma (часть после `?` можно убрать).
2. Примените настройки (в папке `local`):
   ```powershell
   docker compose up -d
   ```
3. Проверьте:
   - в журнале сервера (`docker compose logs -f --tail 50`) есть строка `Связь с VPS установлена`;
   - на панели веб-интерфейса под агентом: «Связь с VPS (Битрикс24): есть»;
   - в Битрикс24 в чате «Ворота» кнопка **📡 Статус** отвечает «🟢 Объект на связи…»;
   - `/add А123ВС77 Тест` в чате: через несколько секунд ответ «✅ А123ВС 77 добавлен», номер
     появился на странице «Номера» веб-интерфейса;
   - в Kuma монитор «Объект: ворота» через минуту стал зелёным.

ПК обменивается данными с VPS раз в 10 секунд (`sync_interval` в `server\config.yaml`).
Поэтому ответ на `/add` и `/del` приходит в течение 10–15 секунд.

Проверка обрыва: выдерните сетевой кабель интернета (или отключите Wi-Fi) на 5 минут.
- **Через ~3 минуты** бот напишет в чат «🔴 Нет связи с объектом». Ворота при этом должны
  открываться по номерам.
- **Через ~5 минут** придёт тревога от Kuma.
- **После подключения кабеля** бот напишет «🟢 Связь с объектом восстановлена», а ПК
  пришлёт сводку за время обрыва.

## Обслуживание

| Действие | Команда (в папке `local`) |
|---|---|
| журнал сервера | `docker compose logs -f --tail 100` |
| перезапуск после правки `config.yaml` | `docker compose restart` |
| после правки `.env` | `docker compose up -d` |
| обновление | `git pull` (или новый ZIP), затем `docker compose up -d --build` |
| перезапуск агента | `Stop-ScheduledTask "GS-LPR Gate Agent"; Start-ScheduledTask "GS-LPR Gate Agent"` |
| резервная копия | папка `data` (база номеров `lpr.db` и снимки) и файлы `.env`, `server\config.yaml` |

После правки `agent.yaml` агент нужно перезапустить.

## Если что-то не работает

- **Нет видео с камеры**: откройте адрес в VLC с этого же ПК. Проверьте, что RTSP включён
  в Protect, порт 7447 и схема `rtsp://`, а не `rtsps://`.
- **Нет связи с VPS**: в журнале сервера ищите `Нет связи с VPS`. Проверьте `VPS_URL`
  (`http://IP-VPS:8080`, без слеша на конце), `VPS_TOKEN` (ошибка `401` означает неверный токен)
  и что адрес `http://IP-VPS:8080/healthz` открывается с этого ПК в браузере.
- **Агент не на связи**: посмотрите `agent\agent.log`. Частые причины: неверный токен
  (должен совпадать с `AGENT_TOKEN` в `.env`), не запущен Docker, занят или неверен COM-порт.
- **Реле не щёлкает при `--test`**: проверьте номер COM-порта и драйвер CH340. Для HID-реле
  раскомментируйте `hidapi` в `requirements.txt` и переустановите: `.\venv\Scripts\pip install hidapi`.
- **После перезагрузки ничего не работает**: проверьте автоматический вход в Windows и
  автозапуск Docker Desktop (раздел 1–2). Агент от них не зависит и стартует сам,
  но без Docker ему не к чему подключаться.
