# Настройка VPS: бот Битрикс24 и Uptime Kuma

На VPS работают два контейнера из папки `vps/`:

| Контейнер | Порт | Что делает |
|---|---|---|
| `gate-bot` | 8080 | чат-бот Битрикс24: уведомления о проездах (с фото), просмотр состояния и журнала, ведение списка номеров (`/add`, `/del`). Сообщает в чат, если объект пропал со связи |
| `kuma` | 3001 | Uptime Kuma: следит, что ПК у ворот присылает сигнал «я жив», и шлёт тревогу, если сигналы пропали |

**Бот воротами не управляет.** Открыть ворота из Битрикс24 нельзя: ворота открываются
только автоматически по номерам из списка или пультом.

```
 сотрудники ⇄ Битрикс24 ⇄ gate-bot :8080 ◄── ПК у ворот раз в 10 с: состояние, список номеров,
                              ▲                события, уведомления; в ответ — правки списка
 тревоги ◄──── kuma :3001 ◄───┘── ПК у ворот раз в минуту: «я жив»
```

- **Запросы всегда начинает ПК у ворот**, постоянного соединения нет. Белый IP на объекте
  и домен не нужны.
- **Основной список номеров хранится на ПК у ворот.** Бот получает его копию и ставит правки
  `/add` и `/del` в очередь, а ПК забирает их при очередном обмене.

Порядок: сначала VPS (эта инструкция), потом ПК у ворот ([local.md](local.md)).

---

## 0. Что понадобится

- **VPS** с Ubuntu 22.04 / 24.04 или Debian 12, от 1 ГБ ОЗУ. Ваш сервер 2 vCPU / 4 ГБ подходит
  с запасом.
- **Права администратора в Битрикс24**, чтобы создать входящие вебхуки.
- На своём компьютере PowerShell (есть в Windows) для подключения по SSH.

Связь ПК с VPS идёт по обычному HTTP. Запросы защищены секретным токеном, но не шифруются:
при перехвате по дороге можно увидеть номера, снимки и токен. Если это станет важно,
позже можно добавить домен и HTTPS.

## 1. Подключиться к VPS

Хостер присылает IP-адрес, логин (обычно `root`) и пароль. В PowerShell:

```powershell
ssh root@203.0.113.10
```

При первом подключении ответьте `yes` и введите пароль (символы при вводе не отображаются).

```bash
apt update && apt upgrade -y
apt install -y git curl nano ufw
```

## 2. Файрвол

```bash
ufw allow 22/tcp      # SSH
ufw allow 3001/tcp    # Uptime Kuma
ufw allow 8080/tcp    # бот (сюда обращается ПК у ворот)
ufw --force enable
```

Если у хостера есть свой файрвол в панели управления, откройте там те же порты.

Если у объекта постоянный (белый) IP, доступ можно ограничить им:
`ufw allow from IP-объекта to any port 8080`.

## 3. Файлы проекта

```bash
cd /opt
git clone https://github.com/torlopkashka/GS_LPR.git gs-lpr
cd /opt/gs-lpr/vps
```

Если репозиторий закрытый, `git` спросит логин и токен GitHub. Можно поступить иначе:
скачать ZIP с GitHub на свой компьютер и скопировать на VPS только папку `vps`:

```powershell
scp -r .\GS_LPR\vps root@203.0.113.10:/opt/gs-lpr/
```

## 4. Битрикс24: вебхук для бота

1. В Битрикс24 под администратором: **Разработчикам → Другое → Входящий вебхук**
   (в старом интерфейсе: **Приложения → Вебхуки → Добавить вебхук → Входящий вебхук**).
2. Название: «Бот ворот». Права доступа: **Чат-боты (imbot)**.
3. Сохраните и скопируйте адрес вида `https://ваш-портал.bitrix24.ru/rest/1/abcdef123456/`.

Адрес вебхука — это пароль к порталу в пределах выбранных прав. Храните его только в `.env`.
Бот работает от имени сотрудника, создавшего вебхук. Если этого сотрудника отключат, бот
перестанет работать, поэтому создавайте вебхук от имени администратора.

**ID сотрудников**, которым доступен бот: откройте профиль сотрудника, в адресе будет
`.../company/personal/user/15/`, где **15** — ID.

## 5. Настроить и запустить

```bash
cd /opt/gs-lpr/vps
sudo sh setup.sh
```

При первом запуске скрипт поставит Docker (если его нет), создаст `.env` со случайными
`B24_BOT_TOKEN` и `SITE_TOKEN` и попросит заполнить остальное:

```bash
nano .env
```

```ini
B24_WEBHOOK_URL=https://ваш-портал.bitrix24.ru/rest/1/abcdef123456/
B24_USER_IDS=1,15,27
```

Сохранить: `Ctrl+O`, `Enter`; выйти: `Ctrl+X`. Запустите скрипт ещё раз:

```bash
sudo sh setup.sh
```

Он соберёт и запустит контейнеры, а в конце покажет две строки для ПК у ворот. Сохраните их:

```
VPS_URL=http://203.0.113.10:8080
VPS_TOKEN=3f9a…
```

Посмотреть их позже: `grep SITE_TOKEN /opt/gs-lpr/vps/.env`.

## 6. Проверка бота

```bash
docker compose ps            # оба контейнера в состоянии Up
docker compose logs -f bot   # выход из просмотра: Ctrl+C
```

В журнале должно появиться `Бот Битрикс24 готов`. В Битрикс24 у сотрудников из `B24_USER_IDS`
появится групповой чат **«Ворота»** со справкой.

В браузере откройте `http://IP-VPS:8080/healthz`:
- `"status": "bot_ok"` — бот подключён к Битрикс24;
- `"site": {"online": false}` — нормально, пока ПК у ворот не настроен.

Если нажать «📡 Статус» до настройки ПК, бот ответит «Объект ещё ни разу не выходил на связь».

## 7. Uptime Kuma

### 7.1. Первый вход

Откройте `http://IP-VPS:3001`, выберите язык **Русский** и создайте учётную запись
администратора Kuma. Придумайте надёжный пароль: панель доступна из интернета по HTTP.

### 7.2. Вебхук Битрикс24 для тревог

Kuma отправляет тревогу системным уведомлением («колокольчик») конкретному сотруднику.
Для этого нужен **второй** входящий вебхук: **Разработчикам → Другое → Входящий вебхук**,
название «Uptime Kuma», права **Мессенджер (im)**. Вебхук бота не подойдёт: у него другие права.

### 7.3. Уведомления

**Настройки → Уведомления → Настроить уведомление**:
- Тип уведомления: **Bitrix24**;
- Название: например «Битрикс24 — Иванов»;
- URL-адрес вебхука Bitrix24: адрес из шага 7.2;
- User ID: ID сотрудника, которому придёт тревога;
- «Тест»: у сотрудника в Битрикс24 должно появиться уведомление.

Одно уведомление Kuma уходит одному сотруднику. Для нескольких получателей создайте по
уведомлению на каждого. Для надёжности можно добавить **SMSC** (SMS через smsc.ru) или
**SMTP** (почта).

Цвет полоски в уведомлении Bitrix24 в Kuma 2.x перепутан. Ориентируйтесь на текст `[DOWN]` / `[UP]`.

### 7.4. Монитор «Объект: ворота» (главный)

**Добавить новый монитор**:
- Тип монитора: **Push**;
- Название: «Объект: ворота»;
- Интервал сердцебиения: **60** секунд;
- Повторы: **4**. Тревога придёт после ~5 минут без сигнала, короткие сбои не беспокоят;
- справа отметьте созданные уведомления;
- **Сохранить**.

Скопируйте **Push URL** вида `http://IP-VPS:3001/api/push/AbCdEf1234?status=up&msg=OK&ping=`.
Он понадобится на ПК у ворот (`HEALTHCHECK_URL`).

ПК у ворот шлёт сюда сигнал раз в минуту:
- `up` — всё в порядке;
- `down` с описанием — если отвалились агент ворот или камера;
- ничего — если пропал интернет или выключился ПК; тогда через ~5 минут придёт тревога.

### 7.5. Монитор «Бот ворот» (рекомендуется)

Чтобы узнать, если сломается сам бот (например, отключили вебхук):
- Тип монитора: **HTTP(s) — Ключевое слово**;
- Название: «Бот ворот»;
- URL: `http://gate-bot:8080/healthz` (внутренний адрес в сети Docker);
- Ключевое слово: `bot_ok`;
- Интервал 60 секунд, отметьте уведомления.

## 8. Обслуживание

Все команды выполняются в папке `/opt/gs-lpr/vps`:

| Действие | Команда |
|---|---|
| состояние контейнеров | `docker compose ps` |
| журнал бота | `docker compose logs -f --tail 100 bot` |
| перезапуск после правки `.env` | `docker compose up -d` |
| обновление бота | `git pull && docker compose up -d --build` |
| обновление Kuma | `docker compose pull kuma && docker compose up -d` |
| резервная копия | папка `data/` (настройки Kuma, состояние бота, очередь правок) и файл `.env` |

- **Новый сотрудник.** Допишите его ID в `B24_USER_IDS` и выполните `docker compose up -d`.
  Бот сам добавит его в чат «Ворота».
- **`B24_BOT_TOKEN` не меняйте** после первого запуска: бот зарегистрирован с этим токеном.

## Если адрес вебхука попал в чужие руки

Адрес входящего вебхука работает как пароль. Если он оказался в переписке, на скриншоте или в
журнале, перевыпустите его:
1. В Битрикс24: **Разработчикам → Интеграции** (или **Приложения → Вебхуки**), откройте вебхук
   «Бот ворот» и удалите его. Создайте новый с теми же правами **Чат-боты (imbot)**.
2. Впишите новый адрес в `B24_WEBHOOK_URL` в `/opt/gs-lpr/vps/.env` и выполните `docker compose up -d`.

Бот и чат «Ворота» сохранятся: бот узнаёт себя по `B24_BOT_TOKEN`, а не по вебхуку.

## Если что-то не работает

- **Прислать журнал для разбора.** Выполните `docker compose logs --tail 200 bot`. Журнал не
  содержит адреса вебхука, но перед отправкой всё равно просмотрите его.

- **В журнале бота ошибки про вебхук.** Проверьте адрес `B24_WEBHOOK_URL` (со слешем в конце)
  и что у вебхука отмечены права «Чат-боты (imbot)».
- **`http://IP-VPS:8080/healthz` не открывается.** Проверьте `docker compose ps`, `ufw status`
  и файрвол в панели хостера.
- **Бот пишет «Нет связи с объектом», хотя ПК включён.** На ПК посмотрите журнал сервера
  (`docker compose logs -f` в папке `local`). Там должна быть строка «Связь с VPS установлена».
  Частые причины: неверный `VPS_URL` или `VPS_TOKEN`.
- **Тест уведомления в Kuma не приходит.** У вебхука Kuma должны быть права «Мессенджер (im)»,
  а User ID — существующий активный сотрудник.
