# Настройка VPS: бот Битрикс24 и Uptime Kuma

На VPS работают три контейнера из папки `vps/`:

| Контейнер | Что делает |
|---|---|
| `gate-bot` | чат-бот Битрикс24. Принимает команды сотрудников и пересылает их на ПК у ворот, присылает уведомления о проездах. Если объект пропал со связи, сам сообщает об этом |
| `kuma` | Uptime Kuma: следит, что ПК у ворот присылает сигнал «я жив», и шлёт тревогу, если сигналы пропали |
| `caddy` | принимает подключения из интернета (порты 80/443), выпускает HTTPS-сертификат и раздаёт запросы: `/link` — боту, остальное — Kuma |

```
 сотрудники ⇄ Битрикс24 ⇄ gate-bot ─┐
                                     ├─ caddy :443 ◄── ПК у ворот (wss://домен/link и /api/push/…)
              тревоги ◄── kuma ──────┘
```

ПК у ворот сам подключается к VPS, поэтому на объекте не нужны белый IP и проброс портов.
Все данные (номера, журнал, снимки) хранятся на ПК у ворот. VPS только передаёт команды
и сообщения.

Порядок настройки: сначала VPS (эта инструкция), потом ПК у ворот ([local.md](local.md)).

---

## 0. Что понадобится

- **VPS** с Ubuntu 22.04 или 24.04 (подойдёт и Debian 12): от 1 ГБ ОЗУ, 10 ГБ диска.
  Ваш сервер 2 vCPU / 4 ГБ подходит с большим запасом.
- **Домен** (рекомендуется), например `vps.example.ru`: нужен для HTTPS. Без домена
  всё тоже работает, но связь ПК с VPS идёт без шифрования (см. раздел «Без домена»).
- **Права администратора в Битрикс24**, чтобы создать входящие вебхуки.
- На своём компьютере: PowerShell (есть в Windows) для подключения по SSH.

## 1. Подключиться к VPS

Хостер присылает IP-адрес, логин (обычно `root`) и пароль. В PowerShell:

```powershell
ssh root@203.0.113.10
```

При первом подключении ответьте `yes` и введите пароль (символы при вводе не отображаются).

Обновите систему и поставьте нужные утилиты:

```bash
apt update && apt upgrade -y
apt install -y git curl nano ufw
```

## 2. Файрвол

Открыть нужно только SSH и веб-порты:

```bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
ufw status
```

> Docker публикует порты в обход ufw, но в нашей конфигурации наружу открыты только 80 и 443
> (Caddy). Kuma и бот наружу напрямую не смотрят.

## 3. Домен

В панели регистратора домена создайте **A-запись**: имя `vps` (или любое другое), значение — IP
вашего VPS. Через 5–30 минут проверьте с любого компьютера:

```powershell
nslookup vps.example.ru
```

Ответ должен содержать IP вашего VPS. Пока запись не заработала, Caddy не сможет выпустить сертификат.

## 4. Файлы проекта

```bash
cd /opt
git clone https://github.com/torlopkashka/GS_LPR.git gs-lpr
cd /opt/gs-lpr/vps
```

Если репозиторий закрытый, `git` спросит логин и токен GitHub. Можно поступить проще:
скачать ZIP с GitHub на свой компьютер и скопировать на VPS только папку `vps`:

```powershell
scp -r .\GS_LPR\vps root@203.0.113.10:/opt/gs-lpr/
```

## 5. Битрикс24: вебхук для бота

1. В Битрикс24 под администратором: **Разработчикам → Другое → Входящий вебхук**
   (в старом интерфейсе: **Приложения → Вебхуки → Добавить вебхук → Входящий вебхук**).
2. Название: «Бот ворот». Права доступа: **Чат-боты (imbot)**.
3. Сохраните и скопируйте адрес вида `https://ваш-портал.bitrix24.ru/rest/1/abcdef123456/`.

Адрес вебхука — это пароль к порталу в пределах выбранных прав. Храните его только в `.env`.
Бот работает от имени сотрудника, создавшего вебхук. Если этого сотрудника отключат, бот
перестанет работать, поэтому создавайте вебхук от имени администратора.

**ID сотрудников**, которым можно управлять воротами: откройте профиль сотрудника, в адресе
будет `.../company/personal/user/15/`, где **15** — ID.

## 6. Настроить и запустить

```bash
cd /opt/gs-lpr/vps
sudo sh setup.sh
```

При первом запуске скрипт поставит Docker (если его нет), создаст `.env` со случайными
`B24_BOT_TOKEN` и `LINK_TOKEN` и попросит заполнить остальное:

```bash
nano .env
```

```ini
SITE_ADDRESS=vps.example.ru
B24_WEBHOOK_URL=https://ваш-портал.bitrix24.ru/rest/1/abcdef123456/
B24_USER_IDS=1,15,27
```

Сохранить: `Ctrl+O`, `Enter`; выйти: `Ctrl+X`. Запустите скрипт ещё раз:

```bash
sudo sh setup.sh
```

Он соберёт и запустит контейнеры, а в конце покажет **LINK_TOKEN**. Скопируйте его: он
понадобится на ПК у ворот. Посмотреть его позже: `grep LINK_TOKEN /opt/gs-lpr/vps/.env`.

## 7. Проверка

```bash
docker compose ps            # три контейнера в состоянии Up
docker compose logs -f bot   # выход из просмотра: Ctrl+C
```

В журнале бота должно появиться `Бот Битрикс24 готов`. В Битрикс24 у сотрудников из
`B24_USER_IDS` появится групповой чат **«Ворота»** со справкой.

Состояние бота из браузера: `https://vps.example.ru/bot/healthz`.
- `"status": "bot_ok"` — бот подключён к Битрикс24;
- `"site": {"online": false}` — нормально, пока ПК у ворот не настроен.

Если бот уже работает, а ПК у ворот ещё не подключён, на кнопки бот ответит
«🔴 Нет связи с объектом». Так и должно быть.

## 8. Uptime Kuma

### 8.1. Первый вход

Откройте `https://vps.example.ru`, выберите язык **Русский** и создайте учётную запись
администратора Kuma (логин и пароль придумайте сами).

### 8.2. Вебхук Битрикс24 для тревог

Kuma отправляет тревогу системным уведомлением («колокольчик») конкретному сотруднику.
Для этого нужен **второй** входящий вебхук: **Разработчикам → Другое → Входящий вебхук**,
название «Uptime Kuma», права **Мессенджер (im)**. Вебхук бота не подойдёт: у него другие права.

### 8.3. Уведомления

**Настройки → Уведомления → Настроить уведомление**:
- Тип уведомления: **Bitrix24**;
- Название: например «Битрикс24 — Иванов»;
- URL-адрес вебхука Bitrix24: адрес из шага 8.2;
- User ID: ID сотрудника, которому придёт тревога;
- «Тест»: у сотрудника в Битрикс24 должно появиться уведомление.

Одно уведомление Kuma уходит одному сотруднику. Для нескольких получателей создайте по
уведомлению на каждого. Для надёжности можно добавить **SMSC** (SMS через smsc.ru)
или **SMTP** (почта).

Цвет полоски в уведомлении Bitrix24 в Kuma 2.x перепутан. Ориентируйтесь на текст `[DOWN]` / `[UP]`.

### 8.4. Монитор «Объект: ворота» (главный)

**Добавить новый монитор**:
- Тип монитора: **Push**;
- Название: «Объект: ворота»;
- Интервал сердцебиения: **60** секунд;
- Повторы: **4**. Тревога придёт после ~5 минут без сигнала, короткие сбои не беспокоят;
- справа отметьте созданные уведомления;
- **Сохранить**.

Скопируйте **Push URL** вида `https://vps.example.ru/api/push/AbCdEf1234?status=up&msg=OK&ping=`.
Он понадобится на ПК у ворот (`HEALTHCHECK_URL`).

ПК у ворот шлёт сюда сигнал раз в минуту:
- `up` — всё в порядке;
- `down` с описанием — если отвалились агент ворот или камера;
- ничего — если пропал интернет или выключился ПК; тогда через ~5 минут придёт тревога.

### 8.5. Монитор «Бот ворот» (рекомендуется)

Чтобы узнать, если сломается сам бот (например, отключили вебхук):
- Тип монитора: **HTTP(s) — Ключевое слово**;
- Название: «Бот ворот»;
- URL: `http://gate-bot:8080/healthz` (внутренний адрес в сети Docker);
- Ключевое слово: `bot_ok`;
- Интервал: 60 секунд, отметьте уведомления.

## 9. Обслуживание

Все команды выполняются в папке `/opt/gs-lpr/vps`:

| Действие | Команда |
|---|---|
| состояние контейнеров | `docker compose ps` |
| журнал бота | `docker compose logs -f --tail 100 bot` |
| перезапуск после правки `.env` | `docker compose up -d` |
| обновление | `git pull && docker compose up -d --build` |
| обновить Kuma и Caddy | `docker compose pull && docker compose up -d` |
| резервная копия | папка `data/` (настройки Kuma, состояние бота) и файл `.env` |

Добавить сотрудника: допишите его ID в `B24_USER_IDS` и выполните `docker compose up -d`.
Бот сам добавит его в чат «Ворота».

Не меняйте `B24_BOT_TOKEN` после первого запуска: бот зарегистрирован с этим токеном.

## Без домена

Если домена нет, в `.env` укажите `SITE_ADDRESS=:80`. Тогда:
- Kuma: `http://IP-VPS`, Push URL: `http://IP-VPS/api/push/...`;
- на ПК у ворот: `VPS_LINK_URL=ws://IP-VPS/link`.

Соединение не шифруется: `LINK_TOKEN` и уведомления можно перехватить по дороге. Для
постоянной работы лучше взять недорогой домен.

## Если что-то не работает

- **`docker compose logs bot` пишет про B24_WEBHOOK_URL / права imbot.** Проверьте адрес
  вебхука (со слешем в конце) и что у вебхука отмечены права «Чат-боты (imbot)».
- **Caddy не выпускает сертификат** (`docker compose logs caddy`). Проверьте A-запись домена
  (`nslookup`) и что порты 80 и 443 открыты (`ufw status`, файрвол в панели хостера).
- **Бот пишет «Нет связи с объектом», хотя ПК включён.** Проверьте на ПК журнал сервера
  (`docker compose logs -f` в папке `local`). Там должна быть строка «Связь с VPS установлена».
  Частые причины: неверный `LINK_TOKEN` или `VPS_LINK_URL`.
- **Тест уведомления в Kuma не приходит.** У вебхука Kuma должны быть права «Мессенджер (im)»,
  а User ID — существующий активный сотрудник.
