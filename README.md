# GS LPR: распознавание номеров и автоматическое открытие ворот

Система для откатных ворот с приводом **NICE RB600** и двумя камерами **UniFi G4 Pro**
(снаружи и внутри). Камеры распознают номер, ПК у ворот сверяет его со списком разрешённых
и открывает ворота. **Уведомления и ведение списка номеров** — через чат-бота **Битрикс24** на VPS.
За связью с объектом следит **Uptime Kuma** на том же VPS.

**Управление воротами отделено от бота.** Ворота открываются только автоматически по номерам
из списка или пультом. Ни бот, ни веб-интерфейс ворота не открывают.

```
 ┌──────────── ПК у ворот (Windows 10) — папка local/ ─────────────┐   HTTP   ┌──── VPS — папка vps/ ────┐
 │                                                                 │ раз в 10 с│                          │
 │  G4 Pro ×2 ─RTSP─► Docker: распознавание, список номеров, ──────┼──────────►│ gate-bot :8080 ⇄ Битрикс24 ⇄ сотрудники
 │                    журнал, веб :8000                    ────────┼──────────►│ kuma :3001 ── тревоги ──► Битрикс24 / SMS
 │                         ▲ ws://127.0.0.1:8000                   │ раз в мин │                          │
 │  Windows: агент ворот ──┘── USB-реле ──► NICE RB600             │           └──────────────────────────┘
 └─────────────────────────────────────────────────────────────────┘
```

- **ПК у ворот** делает всю работу: распознаёт номера, открывает ворота, хранит основной список
  номеров, журнал и снимки. Всё это работает и **без интернета**.
- **ПК сам обращается к VPS** по HTTP:
  - раз в 10 секунд отправляет состояние, копию списка номеров и последние события;
  - в ответ получает правки списка, которые сотрудники отправили боту (`/add`, `/del`);
  - уведомления о проездах с фото отправляет сразу.

  Постоянного соединения, домена и белого IP на объекте нет.
- **Бот на VPS** всегда на связи:
  - отвечает сотрудникам даже когда объект без интернета, показывая последние полученные данные;
  - сообщает в чат, если объект перестал выходить на связь.
- **Uptime Kuma** шлёт тревогу в Битрикс24 или по SMS, если от ПК перестали приходить сигналы.

## Порядок установки

1. **VPS**: [docs/vps.md](docs/vps.md) — вебхук Битрикс24, `setup.sh`, настройка Uptime Kuma.
   Результат: чат «Ворота» в Битрикс24, `VPS_URL` / `VPS_TOKEN` и Push URL для ПК.
2. **ПК у ворот**: [docs/local.md](docs/local.md) — Windows, Docker Desktop, камеры, `setup.ps1`,
   агент ворот, связь с VPS.
3. **Провода к воротам**: [docs/gate-control.md](docs/gate-control.md). Лучше всего реле на вход
   **OPEN** (или **SbS**) блока управления RB600.

## Как пользоваться ботом

В чате «Ворота» в Битрикс24 под сообщениями бота есть кнопки:

| Кнопка | Что делает |
|---|---|
| 📡 Статус | на связи ли объект, агент ворот и камеры; последний номер |
| 🕘 Последние | последние 10 событий |
| 📋 Номера | список разрешённых номеров и правки, которые ждут применения |

Команды:

```
/add А123ВС77 Иванов                 добавить номер
/add А123ВС77 Гость до 31.12.2026    временный доступ
/del А123ВС77                        удалить номер
```

Правка уходит на ПК у ворот при следующем обмене. Ответ «✅ добавлен» или «🗑 удалён»
приходит в течение 10–15 секунд. Если объект без интернета, правка применится, когда связь
вернётся.

Уведомления:
- ✅ проезд разрешён — с фото;
- ⛔ неизвестный номер — с фото и кнопкой **«➕ В список»**;
- ⚠️ агент ворот или камера не на связи, ✅ когда восстановились;
- 🔴 нет связи с объектом (через 3 минуты), 🟢 связь восстановлена и сводка за время обрыва.

Боту доступны только сотрудники из `B24_USER_IDS` (настройка на VPS). Список номеров можно вести
и в веб-интерфейсе на ПК у ворот: `http://IP-ПК:8000`.

## Если пропал интернет на объекте

| | Что происходит |
|---|---|
| распознавание и автоматическое открытие | ✅ работают по списку номеров на ПК |
| пульты, веб-интерфейс в локальной сети | ✅ работают |
| «📡 Статус» в боте | «🔴 Нет связи с объектом с 14:05» и последние данные от объекта |
| `/add`, `/del` | сохраняются на VPS и применятся, когда связь вернётся |
| через 3 минуты | бот пишет в чат «🔴 Нет связи с объектом» |
| через ~5 минут | тревога от Uptime Kuma (Битрикс24, SMS) |
| после восстановления | «🟢 Связь восстановлена» и сводка: сколько машин проехало и получило отказ |

## Настройка распознавания

Всё настраивается в `local\server\config.yaml` (с комментариями). Главное:

1. **Зона интереса `roi`.** На панели видно превью с оранжевой рамкой зоны. Оставьте в
   ней только место, где машина стоит перед воротами. Это ускоряет работу и отсекает
   номера машин, проезжающих по улице.
2. **Размер номера в кадре**: от ~120 px в ширину. У G4 Pro есть оптический зум,
   увеличьте картинку на зону у ворот. Номер должен быть виден спереди, под углом не больше ~30°.
3. **Ночью** ИК-подсветка хорошо «проявляет» светоотражающие номера. Проверьте по превью,
   что номер не засвечен фарами. Если засвечен, уменьшите экспозицию в Protect.
4. `min_confirmations: 2`: номер должен прочитаться одинаково дважды. Это компромисс
   между скоростью (~0,5–1 с) и защитой от ошибок.
5. `max_distance: 0`: открывать только при полном совпадении. Путаница похожих символов
   (0/O, 8/B, 1/I) учитывается всегда. Значение `1` допускает одну ошибку OCR.
6. Для камеры на выезд можно поставить `open_policy: any`: ворота откроются любой машине,
   у которой распознан номер.

Изменения `config.yaml` применяются после `docker compose restart` (в папке `local`).

### Точность и безопасность

Распознавание номеров не даёт 100%, поэтому пульт остаётся основным запасным способом
открыть ворота. Система сохраняет вырезки номеров, и по журналу видно, какие номера
читаются с ошибками. Поддельный номер (распечатка) откроет ворота так же, как настоящий.
Это ограничение любой системы на распознавании номеров.

## API сервера у ворот

В локальной сети, с заголовком `Authorization: Bearer <API_TOKEN>` (задаётся в `local/.env`):

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/status` | состояние агента, камер, связи с VPS |
| GET | `/api/events?limit=20` | последние события |
| GET / POST | `/api/plates` | список / добавить `{"plate": "А123ВС77", "owner": "...", "valid_until": "2026-12-31"}` |
| DELETE | `/api/plates/{номер}` | удалить номер |
