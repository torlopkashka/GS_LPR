# GS LPR: распознавание номеров и автоматическое открытие ворот

Система для откатных ворот с приводом **NICE RB600** и двумя камерами **UniFi G4 Pro**
(снаружи и внутри). Камеры распознают номер, сервер сверяет его со списком разрешённых
и, если номер в списке, открывает ворота.

- распознавание на CPU (нейросети YOLOv9 + OCR в формате ONNX, ~40 мс на кадр), без GPU;
- исправление типичных ошибок OCR с учётом формата российских номеров (0↔O, 8↔B и т.п.);
- номер подтверждается по нескольким кадрам, прежде чем ворота откроются;
- веб-интерфейс: живое превью камер, кнопка «Открыть», список номеров со сроком действия
  (гостевой доступ), журнал проездов со снимками, импорт/экспорт CSV;
- уведомления в Telegram с кнопками **«Открыть ворота»** и **«В список»**
  для незнакомых машин, команда `/open`;
- защита от двойного импульса: одна машина, увиденная обеими камерами, не остановит ворота;
- агент у ворот работает с USB-реле, Wi-Fi-реле (Shelly), GPIO Raspberry Pi или ESPHome.

## Архитектура

```
 Камеры G4 Pro ─► UniFi Protect (RTSP) ─► WireGuard ─► VPS: сервер распознавания
                                                         │  веб-интерфейс, Telegram
                                                         ▼  WebSocket (исходящий от агента)
 NICE RB600 ◄── реле ◄── агент на компьютере у ворот ◄───┘
```

| Компонент | Где | Что делает |
|---|---|---|
| `server/` | VPS (Docker) | читает потоки, распознаёт номера, принимает решения, веб-интерфейс |
| `agent/` | компьютер у ворот | держит связь с сервером и замыкает реле по команде |
| `deploy/` | VPS | Caddy (HTTPS), примеры конфигов WireGuard |

Подробнее: **[подключение к воротам](docs/gate-control.md)**, **[сеть и RTSP](docs/network.md)**.

### Как лучше подавать команду на ворота

Радиопульт с реле работает, но лучше подключить **реле напрямую к клеммам блока управления RB600**:
вход **OPEN** («только открыть»), либо **SbS**. Это надёжнее (нет батарейки и радиопомех),
и с входом OPEN повторная команда не остановит ворота. Реле можно взять USB
(на компьютере у ворот) или Wi-Fi (Shelly в корпусе привода).
Все варианты со схемами описаны в [docs/gate-control.md](docs/gate-control.md).

### Хватит ли VPS (2 vCPU / 4 ГБ)

Да. Две камеры в потоке 1280×720: декодирование видео плюс анализ 4 кадров/с на камеру
занимают примерно 0,8–1,3 ядра, памяти нужно около 700 МБ. Анализ запускается только при движении в
кадре. Если нагрузка высокая, уменьшите `process_fps`, задайте `roi` (зону интереса) или снизьте FPS
потока в Protect.

## Установка

### 1. Сеть (один раз)
Поднимите туннель WireGuard между VPS и компьютером у ворот и включите RTSP на камерах
в UniFi Protect: [docs/network.md](docs/network.md).

### 2. Сервер на VPS

```bash
# Docker
curl -fsSL https://get.docker.com | sh

git clone <этот репозиторий> /opt/gs-lpr && cd /opt/gs-lpr
cp .env.example .env
cp server/config.example.yaml server/config.yaml
```

В `.env` задайте домен, пароль администратора и случайные ключи
(`openssl rand -hex 32` для `SECRET_KEY` и `AGENT_TOKEN`). В `server/config.yaml`
пропишите RTSP-адреса камер.

A-запись домена (например `lpr.example.ru`) должна указывать на IP VPS. Затем:

```bash
docker compose up -d --build
docker compose logs -f lpr
```

Откройте `https://lpr.example.ru` и войдите с логином и паролем из `.env`.

> Без домена: в `docker-compose.yml` раскомментируйте `ports: "8000:8000"`, уберите
> сервис `caddy` и поставьте `COOKIE_SECURE=0`. Интерфейс тогда лучше открывать только через
> WireGuard (`http://10.8.0.1:8000`).

### 3. Агент на компьютере у ворот

Linux (Debian/Ubuntu/Raspberry Pi OS):

```bash
cd agent
sudo ./install.sh
sudo nano /opt/gate-agent/agent.yaml      # адрес сервера, AGENT_TOKEN, тип реле
sudo -u gateagent /opt/gate-agent/venv/bin/python /opt/gate-agent/gate_agent.py \
     -c /opt/gate-agent/agent.yaml --test  # реле должно щёлкнуть
sudo systemctl enable --now gate-agent
```

Windows: установите Python 3.10+, затем `pip install -r requirements.txt` и
`python gate_agent.py -c agent.yaml`. Для автозапуска используйте Планировщик заданий или NSSM.

На панели должно появиться «Агент ворот: на связи». Кнопка «Открыть ворота» проверяет всю цепочку.

### 4. Telegram (необязательно)

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен запишите в `TELEGRAM_TOKEN`.
2. Напишите боту `/start`. Свой chat id узнайте у [@userinfobot](https://t.me/userinfobot)
   (для группы добавьте бота в группу и возьмите id группы).
3. Запишите id в `TELEGRAM_CHAT_IDS` (можно несколько через запятую), затем
   `docker compose up -d`.

Команды и кнопки принимаются только из чатов, перечисленных в `TELEGRAM_CHAT_IDS`.

## Настройка распознавания

Всё настраивается в `server/config.yaml` (с комментариями). Главное:

1. **Зона интереса `roi`.** На панели видно превью с оранжевой рамкой зоны. Оставьте в
   ней только место, где машина стоит перед воротами. Это ускоряет работу и отсекает
   номера машин, проезжающих по улице.
2. **Размер номера в кадре.** Номер должен быть шириной от ~120 px. У G4 Pro есть
   оптический зум, увеличьте картинку на зону у ворот. Номер должен быть виден
   спереди, желательно под углом не больше 30°.
3. **Ночью** ИК-подсветка G4 Pro хорошо «проявляет» светоотражающие номера. Проверьте
   по превью, что номер не засвечен фарами. Если засвечен, уменьшите экспозицию в Protect.
4. `min_confirmations: 2`: номер должен прочитаться одинаково дважды. Это компромисс
   между скоростью (~0,5–1 с) и защитой от ошибок.
5. `max_distance: 0`: открывать только при полном совпадении. Путаница похожих символов
   (0/O, 8/B, 1/I) учитывается всегда. Значение `1` допускает одну ошибку OCR, но немного
   снижает безопасность.
6. Для камеры на выезд можно поставить `open_policy: any`: ворота откроются любой машине,
   у которой распознан номер.

Изменения конфигурации применяются после `docker compose restart lpr`.
Список номеров меняется в интерфейсе сразу, без перезапуска.

### Точность и безопасность

Распознавание номеров не даёт 100%, поэтому:
- пульты и ручное открытие (веб, Telegram) остаются рабочими;
- система сохраняет вырезки номеров (`data/snapshots/*_plate.jpg`). Если конкретный номер
  часто читается с ошибкой, по журналу это сразу видно;
- поддельный номер (распечатка) откроет ворота так же, как настоящий. Это ограничение
  любой системы на распознавании номеров. Для охраняемых объектов добавьте второй фактор
  (метку, пульт).

## Вариант размещения: всё на объекте

Если на объекте есть мини-ПК от 4 ядер, сервер можно запустить прямо там той же командой
`docker compose up -d` (адреса камер тогда локальные). Плюсы: распознавание работает
даже без интернета, не нужен WireGuard, нет нагрузки на канал. VPS в этом случае можно
оставить только для внешнего доступа к интерфейсу (например, через тот же WireGuard).

## API

С заголовком `Authorization: Bearer <API_TOKEN>`:

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/open` | открыть ворота |
| GET | `/api/status` | состояние агента и камер |
| GET | `/api/events?limit=20` | последние события |
| GET / POST | `/api/plates` | список / добавить `{"plate": "А123ВС77", "owner": "...", "valid_until": "2026-12-31"}` |
| DELETE | `/api/plates/{номер}` | удалить номер |

Пример ярлыка «Открыть ворота» для телефона:
`curl -X POST -H "Authorization: Bearer $API_TOKEN" https://lpr.example.ru/api/open`

## Разработка

```bash
cd server
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
python -m pytest -q
```

Данные (SQLite, снимки) лежат в `./data`. Журнал и снимки старше `retention_days` удаляются автоматически.
