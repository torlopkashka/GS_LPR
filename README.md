# GS LPR: распознавание номеров и автоматическое открытие ворот

Система для откатных ворот с приводом **NICE RB600** и двумя камерами **UniFi G4 Pro**
(снаружи и внутри). Камеры распознают номер, сервер сверяет его со списком разрешённых
и, если номер в списке, открывает ворота. Всё работает на **одном ПК с Windows 10 рядом с воротами**:
сервер в Docker Desktop, агент управления реле прямо в Windows.

- распознавание на CPU (нейросети YOLOv9 + OCR в ONNX, ~40 мс на кадр), без GPU;
- исправление типичных ошибок OCR с учётом формата российских номеров (0↔O, 8↔B и т.п.);
- номер подтверждается по нескольким кадрам, прежде чем ворота откроются;
- **работает без интернета**: интернет нужен только Telegram-боту;
- веб-интерфейс в локальной сети: превью камер, кнопка «Открыть», список номеров
  со сроком действия, журнал проездов со снимками, импорт/экспорт CSV;
- **Telegram-бот**: кнопки «Открыть ворота», «Статус», «Последние проезды», «Номера»;
  добавление номеров командой `/add`; уведомления с фото и кнопками «Открыть» / «В список»
  для незнакомых машин; предупреждения, если агент или камера пропали; отчёт после
  восстановления интернета;
- защита от двойного импульса: одна машина, увиденная обеими камерами, не остановит ворота.

```
 G4 Pro ×2 ─► UniFi Protect ── RTSP (LAN) ──┐
                                             ▼
 ┌─────────────── ПК у ворот, Windows 10 ────────────────┐
 │ Docker: сервер распознавания, веб :8000, Telegram-бот  │──► интернет (только Telegram
 │            ▲ ws://127.0.0.1:8000                       │    и внешний сторож)
 │ Windows: агент ворот ── USB-реле ──────────────────────┼──► NICE RB600 (вход OPEN/SbS)
 └────────────────────────────────────────────────────────┘
```

| Папка | Что это |
|---|---|
| `server/` | сервер распознавания, веб-интерфейс и Telegram-бот (Docker) |
| `agent/` | агент ворот: принимает команды сервера и замыкает реле (Python в Windows) |
| `docs/` | инструкции |

## Установка

Пошагово: **[docs/windows.md](docs/windows.md)**. Коротко:

1. Подготовьте Windows к работе без присмотра: включение после пропажи питания,
   без сна, автоматический вход, автозапуск Docker Desktop.
2. Включите RTSP на камерах в UniFi Protect.
3. В папке проекта выполните `powershell -ExecutionPolicy Bypass -File .\setup.ps1`, затем
   впишите адреса камер в `server\config.yaml` и выполните `docker compose restart`.
4. Установите агент от имени администратора: `agent\install-windows.ps1`. Проверьте реле
   командой `--test`.
5. Настройте Telegram-бота и внешнего сторожа: **[docs/telegram.md](docs/telegram.md)**.

Веб-интерфейс: `http://IP-компьютера:8000`, логин `admin`, пароль задаётся при установке.

## Подключение к воротам

Лучше всего подключить **реле напрямую к клеммам блока управления RB600**:
вход **OPEN** («только открыть»), либо **SbS**. Это надёжнее радиопульта (нет батарейки
и помех), а с входом OPEN повторная команда не остановит ворота. Реле: USB (CH340 или HID) у компьютера
или Wi-Fi (Shelly) в корпусе привода. Все варианты описаны в **[docs/gate-control.md](docs/gate-control.md)**.

## Отключения интернета

| | Без интернета |
|---|---|
| распознавание и автоматическое открытие | ✅ работает |
| пульты | ✅ работают |
| веб-интерфейс в локальной сети | ✅ работает |
| Telegram-бот | ❌ не отвечает. Команды, накопившиеся за время обрыва, после восстановления **не выполняются** |
| уведомление об обрыве | через внешний сторож healthchecks.io (~5 минут) |
| после восстановления | бот присылает отчёт: сколько не было связи и что происходило у ворот |

Кнопка **«📡 Статус»** в боте: если ответ пришёл, сервер работает и интернет есть, а в ответе
видно, на связи ли агент ворот и камеры. Если ответа нет, на объекте нет интернета или
выключен ПК. Подробнее: [docs/telegram.md](docs/telegram.md).

## Настройка распознавания

Всё настраивается в `server\config.yaml` (с комментариями). Главное:

1. **Зона интереса `roi`.** На панели видно превью с оранжевой рамкой зоны. Оставьте в
   ней только место, где машина стоит перед воротами. Это ускоряет работу и отсекает
   номера машин, проезжающих по улице.
2. **Размер номера в кадре**: от ~120 px в ширину. У G4 Pro есть оптический зум,
   увеличьте картинку на зону у ворот. Номер должен быть виден спереди, под углом не больше ~30°.
3. **Ночью** ИК-подсветка хорошо «проявляет» светоотражающие номера. Проверьте по превью,
   что номер не засвечен фарами. Если засвечен, уменьшите экспозицию в Protect.
4. `min_confirmations: 2`: номер должен прочитаться одинаково дважды. Это компромисс
   между скоростью (~0,5–1 с) и защитой от ошибок.
5. `max_distance: 0`: открывать только при полном совпадении. Путаница похожих символов
   (0/O, 8/B, 1/I) учитывается всегда. Значение `1` допускает одну ошибку OCR.
6. Для камеры на выезд можно поставить `open_policy: any`: ворота откроются любой машине,
   у которой распознан номер.

Изменения `config.yaml` применяются после `docker compose restart`. Список номеров
меняется в интерфейсе или боте сразу.

### Точность и безопасность

Распознавание номеров не даёт 100%, поэтому пульты и ручное открытие (веб, Telegram)
остаются рабочими. Система сохраняет вырезки номеров, и по журналу видно, какие номера
читаются с ошибками. Поддельный номер (распечатка) откроет ворота так же, как настоящий.
Это ограничение любой системы на распознавании номеров.

## API

С заголовком `Authorization: Bearer <API_TOKEN>` (задаётся в `.env`):

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/open` | открыть ворота |
| GET | `/api/status` | состояние агента, камер, связи с интернетом |
| GET | `/api/events?limit=20` | последние события |
| GET / POST | `/api/plates` | список / добавить `{"plate": "А123ВС77", "owner": "...", "valid_until": "2026-12-31"}` |
| DELETE | `/api/plates/{номер}` | удалить номер |

## Разработка

```bash
cd server
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
python -m pytest -q
```

Данные (SQLite, снимки) лежат в `data\`. Журнал и снимки старше `retention_days` удаляются автоматически.
